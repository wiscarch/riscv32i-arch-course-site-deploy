Project 6: Multi-Cycle Memory

UW—Madison ECE 552: Fall 2026

Project Introduction

In this project phase, you will adapt your processor from Project 5 to be able to handle a memory that has more than one cycle of latency. You will also create a schematic for a cache that you will implement in Project 7.

Implementations must be created using Verilog; SystemVerilog will not be allowed and will result in a grade of 0 for Problem 1 if used. This assignment is designed to be completed in a group of 2-3. Collaboration between groups is not permitted. IMPORTANT: Make your final submissions in your groups on Gradescope. If you do not, the teaching staff will have to do this manually.

Generative artificial intelligence (e.g. ChatGPT) may not be used to write code, create schematics, or debug for this assignment; all Verilog, schematics, and debugging must be your group's own work. AI may be used for supplementary activities, such as writing sample assembly programs, but any such use must be disclosed in an ai_disclosure.txt file submitted with your project. The disclosure must describe what AI was used for and include the prompts that were used. ai_disclosure.txt is required even if you did not use AI; in that case, it should state "We did not use generative AI for any part of this assignment."

This project will be worth 2.5% of your final course grade. The automated tests on Gradescope cover most of the points for the project, but the schematic is worth a fair portion.

All material is available in the Project 6 and 7 repository on GitHub. You can clone the repository locally or on a CSL machine.

If there are any issues with Gradescope or the files provided, please post on Piazza rather than emailing. If you are having difficulty with this project, office hours are held several times a week where assistance is available.

Good luck!

Problem 1: Multi-Cycle Memory Implementation

The testbench from the previous projects has been updated to use a multi-cycle memory rather than one with zero-cycle latency. This testbench can be found in the Project 6 and 7 repository on GitHub.

The hart interface has also been updated; it can be found in the repository. There is also a file called tb_memory.v, which is the stalling memory module used for grading. Do not submit tb_memory.v to Gradescope.

Note that both the instruction and data memories will now stall before servicing requests. Note also that your optimizations from Project 5 effectively become useless due to this. In Project 7, you will add a cache which will enable zero-cycle latency for cached addresses and make your optimizations effective again.

As in previous project phases, Verilog coding rules are still enforced (see the Verilog Rules page) -- you can run the exact same checker locally before submitting: ece552 validate -w *.v (see the starter repository's python-ece552/README.md for setup).

Problem 2: Cache Schematic

Create a schematic for the finite state machine for a two way set-associative cache. The cache should follow the write-through and write-allocate policies.

The cache must use the following parameters:

Parameter Value
Total capacity 1 KB (32 sets × 2 ways × 16-byte lines)
Associativity 2-way set-associative
Number of sets 32 (5-bit set index)
Line size 16 bytes / 4 words (4-bit offset)
Tag 23 bits (32 − 5 − 4)
Replacement policy NMRU (replace the way that was not most recently used)
Write policy Write-through, write-allocate
Memory access Word granularity (byte masking is done inside the cache)

You will create this cache module in Project 7, which is now available.
