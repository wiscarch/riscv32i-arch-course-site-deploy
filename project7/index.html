Project 7: Cache Integration

UW—Madison ECE 552: Fall 2026

Project Introduction

In this project phase, you will design and implement a two way set-associative cache which will reduce the overall CPI of your processor. This is the last required project for ECE 552.

Implementations must be created using Verilog; SystemVerilog will not be allowed and will result in a grade of 0 for Problems 1 and 2 if used. This assignment is designed to be completed in a group of 2-3. Collaboration between groups is not permitted. IMPORTANT: Make your final submissions in your groups on Gradescope. If you do not, the teaching staff will have to do this manually.

Generative artificial intelligence (e.g. ChatGPT) may not be used to write code, create schematics, or debug for this assignment; all Verilog, schematics, and debugging must be your group's own work. AI may be used for supplementary activities, such as writing sample assembly programs, but any such use must be disclosed in an ai_disclosure.txt file submitted with your project. The disclosure must describe what AI was used for and include the prompts that were used. ai_disclosure.txt is required even if you did not use AI; in that case, it should state "We did not use generative AI for any part of this assignment."

This project will be worth 7.5% of your final course grade. The automated tests on Gradescope comprise the majority of the points (mostly performance for this project); there is no schematic requirement for this phase.

All material is available in the Project 6 and 7 repository on GitHub. You can clone the repository locally or on a CSL machine.

If there are any issues with Gradescope or the files provided, please post on Piazza rather than emailing. If you are having difficulty with this project, office hours are held several times a week where assistance is available.

Good luck!

Problem 1: Cache Implementation

Implement the cache from the schematic that you designed in Project 6. The starter file, cache.v, is available in rtl folder in the Project 6 and 7 repository on GitHub. You can submit this file alone to Gradescope to determine whether or not your cache is functional.

The cache testbench and memory file are also available in the repository in the tb folder.

The cache should follow the write-through and write-allocate policies, and use the parameters listed in Project 6, Problem 2 (1 KB, 32 sets, 2-way, 16-byte lines, NMRU replacement).

Problem 2: Cache Integration

Integrate your cache into your processor implementation. You can do this by hooking the cache signals up to the memory interface signals in your processor. You can implement the caches in any order, but it is recommended to first add in the instruction cache, then the data cache.

Your code should pass correctness tests on Gradescope before the caches are added, after one of them is added, and after both are added. Your code should pass performance tests once both caches are added.

As in previous project phases, Verilog coding rules are still enforced (see the Verilog Rules page) -- you can run the exact same checker locally before submitting: ece552 validate -w *.v (see the starter repository's python-ece552/README.md for setup).
